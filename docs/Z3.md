## Base patch (done)

`tools/z3/build_z3_ips.sh` extracts z3randomizer at the pin, copies the JP 1.0 ROM (`rom/alttp_jp_v1.sfc`, MD5
`03a63945398191337e896e5771f77173`) and runs `asar --fix-checksum=off LTTP_RND_GeneralBugfixes.asm`, exactly what
`UpdateBuildRecord` does. asar grows the ROM to 2 MB.

- Built ROM MD5: `edc01f3db798ae4dfe21101311598d44`, which equals `Rom::HASH`.
- `patches/z3_base.ips` (186891 bytes, MD5 `21c1f78916d2ee4a81b6d34f511b3f83`): written by `tools/z3/make_ips.py`
  against the JP ROM zero-padded to 2 MB, then replayed and compared with the built ROM. A reader must grow the ROM to
  2 MB (zero-filled) before applying it, as `Rom::resize()` does.
- `tools/z3/gen_z3_ips_c.py` embeds it as `Z3_BASE_IPS` / `Z3_BASE_IPS_LEN` (`build/z3gen/z3_ips_data.c`, like
  `gen_sm_ips_c.py`). No host Makefile references it yet.

## PHP oracle (image built, not run)

`tools/z3/oracle/Dockerfile`: `php:8.1.29-cli-bookworm` (alttpr's `platform-overrides` is PHP 8.1), composer 2.7.7,
alttpr fetched at the pinned commit, `composer install --no-dev --no-scripts` from its `composer.lock` (which pins
z3/randomizer at `dcb0a2b4`). Image `smz3u-z3oracle:219fcafd`; build or run with `tools/z3/oracle/oracle.sh`.

Seeding: alttpr's only randomness is `get_random_int()` (`app/Helpers/number.php`, `random_int`). The Dockerfile
rewrites its body to `empty($GLOBALS["Z3_ORACLE_SEEDED"]) ? random_int($min, $max) : mt_rand($min, $max)`;
`oracle_seed(n)` in `z3oracle.php` calls `mt_srand(n, MT_RAND_MT19937)` and sets the flag. Only the container's copy
is patched; without a seed the generator is upstream's. (Enemizer's own seed also uses `random_int`, out of scope.)

`tools/z3/oracle/z3oracle.php` verbs (all print names, not numbers):

| Verb | Mirrors | Prints |
|---|---|---|
| `schema <out.json>` | `gen-cli schema` | build, hash, the option lists of `config('alttp.randomizer.item')`, item names |

## Logic transpiler (Open and Standard, No Glitches: parses completely)

`tools/z3/port_world_php.py` reads `World/Open.php` and `World/Standard.php` (26 region keys each; only `Escape`
differs), the 27 region classes they use, `Boss.php`, `Item.php` and `config/logic.php`, and writes
`core/z3gen/z3_world_gen.{h,c}`. It parses the PHP into an expression tree (closures, `if`/`return`,
ternaries, `in_array`, `is_a`, `instanceof`, `itemInLocations`, local closures such as Turtle Rock's `$upper`), so
nothing is hand-patched: the run ends with no TODO.

Output: 179 items (176 + the aliases UncleSword, ShopKey, ShopArrow) with class and byte, 12 bosses, 26 regions,
236 locations (kind, region, first ROM address), 41 shops, 43 config keys (`Z3Cfg`, enums for the string ones), and
`z3_region_enter`, `z3_region_complete`, `z3_loc_req`, `z3_loc_fill`, `z3_loc_always`, `z3_shop_req`,
`z3_boss_beat`, `z3_region_item`, `z3_loc_exists`, `z3_world_defaults`, `z3_cfg_defaults`, `z3_cfg_logic`. Where Open
and Standard use different classes (`Escape`) the dispatch picks by `cfg.mode_state`. The glitch switches in the same
closures (`canOWYBA`, `canBootsClip`, ...) are config flags filled from `config/logic.php`, so Overworld and Major
Glitches logic is already transpiled, unchecked.

Hand-written in `core/z3gen/z3_world.{h,c}`: `Z3Items`, `Z3World`, `ItemCollection::has` and its helpers,
`World::__construct`'s config switches (`z3_cfg_derive`), `Location::canAccess`/`canFill`, `Region::canFill`,
`World::collectItems`.

## Seeded PRNG (done)

`core/z3gen/z3_rng.{h,c}`: PCG32 (XSH RR), seeded through splitmix64. Integer-only, 16 bytes of state, cheap on the
3DS's ARM11, and with published reference outputs (`z3_rng_init_pcg` is `pcg32_srandom_r`). `z3_rng_int(min, max)`
is `get_random_int` (inclusive, unbiased by rejection), `z3_rng_shuffle` draws in `fy_shuffle`'s order.

## Open problems

- `World::collectItems()` keeps `collected_locations` across calls, so a second call within one fill skips items the
  first one collected (Link's Uncle's fill rule calls it). `z3_collect` sweeps fresh each time. Harmless for logic
  parity tests; it can change which items Uncle may hold during a fill.
- Shop inventories are collectable in PHP (`getCollectableLocations` merges `ShopCollection::getLocations`) and are not
  in `z3_collect` yet; they come with `setShops`.
- `ItemCollection::has($x, null)` is false in PHP but `z3_has(x, 0)` is true: only `item.Goal.Required`, which
  `z3_cfg_derive` sets for the hunt goals, can be missing.
- The Blacksmith's address depends on `region.swordsInPool`; the table keeps the default (true) one.
- Without a database the PHP writes the five hash icons only when saving a seed record, so the oracle pins them with
  `override_start_screen`; `placementrom` also calls `setTexts`/`randomizeCredits`, whose random text choices differ
  from C, so ROM comparisons skip texts as in SMZ3.
