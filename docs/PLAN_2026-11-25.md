### 1.2 Decoder
- No MP3/OGG decoder exists in the tree. Vendor `dr_mp3.h` (mackron/dr_libs, public domain or MIT-0, one header) as
  `core/common/dr_mp3.h`, pinned to a tagged release; note it in `THIRD_PARTY.md`.
- PC and 3DS decode with it. Android plays the file with `android.media.MediaPlayer`, which decodes MP3 itself.

### 1.3 Shared UI (core/ui)
- The Options list already has a `UI_OPT_SOUND` row ("Sound", "music, chime, rival notes") that no host enables, and no
  host has a Sound page. Turn that row into the toggle: name "Menu music", right-hand text "on"/"off" from a new
  `SmzUi.menu_music` field.
- A on the row flips `menu_music` in the core and returns `ACT_OPTIONS` with `action_slot = UI_OPT_SOUND`, so the host
  saves the value and starts or stops the music. `ui_init` resets the field to on, so every host calls
  `ui_menu_music(SmzUi *, int on)` with its saved value after each `ui_init`: once at start-up on PC, in `runMenu()`
  after its `ui_init` on 3DS (the menu is made again after every game), and after `Smz3Native.uiInit()` in
  `NativeMenuScreen` on Android, through a new JNI export (`uiMenuMusic` in `smz3_jni.c` and `Smz3Native.kt`).
- Default: on.
- Every host adds `UI_OPT_SOUND` to its `ui_home_enable` mask.

### 1.4 When it plays
- While the launcher's menus are up (logo, game carousel, start menu, Options, run lists, setup, online screens), if the
  toggle is on. Stops while a game runs, fading out over half a second (the owner, 2026-11-25); every return to the
  menu starts the track from the beginning. Loops at the end.
- Volume 50%: samples scaled by 0.5 on PC and 3DS, `setVolume(0.5f, 0.5f)` on Android.

### 1.5 PC (`frontends/pc`)
- New `pc_menumusic.c/.h`: its own SDL stereo device at the file's rate, an SDL audio callback that pulls frames from
  `drmp3` (opened on the file in memory) and seeks to frame 0 at the end; `menumusic_set(int on)` pauses or unpauses.
- The MP3 goes into the executable the way the other assets do (a generated C array, Makefile rule beside
  `logo_data.c`), so the Windows/macOS/Linux packages need no extra file.
- `pc_main.c`: pause before `play()` and resume after it returns; the `ACT_OPTIONS`/`UI_OPT_SOUND` case saves
  `menu_music=0|1` with the video settings (`video.cfg`, `video_save`/`settings_video_load`) and calls `menumusic_set`.

### 1.6 Android (`vendor/Lemuroid`, patch `patches/lemuroid-tracker.patch`)
- The build copies `assets/music/smz3_intro.mp3` into `lemuroid-app/src/main/assets/smz3/` (MP3 is stored uncompressed
  in the APK, so `assets.openFd` works).
- A small `Smz3MenuMusic` object owns one looping `MediaPlayer`. `NativeMenuScreen`: start on `ON_RESUME` when the
  toggle is on, pause on `ON_PAUSE` and when a game launches (the game runs in the `:game` process, so `ON_PAUSE`
  covers it), release on dispose.
- Preference: `menu_music` boolean in the app's SharedPreferences, as `Smz3Shortcuts` stores its booleans.
- `Act.OPTIONS` with the Sound slot flips the preference and starts or pauses the player.

### 1.7 3DS (`vendor/snes9x_3ds`, patch `patches/snes9x_3ds-smz3.patch`)
- `build-3ds.sh` copies the MP3 to `romfs/smz3/smz3_intro.mp3` and `dr_mp3.h` next to the sources.
- New `smz3music.cpp`: `ndsp` channel 5 (the emulator plays on channel 0 and `smz3run.cpp`'s sound effects on channels
  1 to 4), a few `linearAlloc` wave buffers of about 100 ms each, refilled by a thread on the app core at a higher
  priority than the menu loop. The thread wakes on a short sleep and refills the buffers marked done; it does not use
  `ndspSetCallback`, whose one slot `3dssound.cpp` already takes. `drmp3` reads the romfs file in chunks through read/seek callbacks, so the 4.9 MB file is never held in RAM.
- The decoder and its romfs file stay open between stops (a few tens of KB); a start seeks it back to frame 0, which
  on a callback stream is a plain rewind. The stop lowers the channel's mix to silence over half a second first.
- Start in `smz3Home()` when the toggle is on; stop and free (thread, wave buffers) before `EMUSTATE_EMULATE` and
  before each `generateRun` (run, daily and race builds in `smz3run.cpp`, all inside `smz3RunMenu()`). Start again when
  `showMenu()` returns to `smz3Home`, and right after a `generateRun` that leaves the player in the menu (a failed
  build, or a race build that goes to the ready room).
- Setting saved as `menu_music.txt` ("0"/"1") under `SMZ_DIR`, like `shortcuts.txt`.
- `heapNote()` (static in `smz3run.cpp`) runs only inside `generateRun`, where the music is already stopped; add one
  call after the music starts in the menu, written to `gen.log`, to read the heap while it plays on the Old 3DS
  profile in Azahar.

## 4. World goals per game (the owner, 2026-11-25)

ALttP and Super Metroid show SMZ3's world goals: `server/ladder/goals.js` has one set of goals a month for every
game. Each game gets its own.

### 4.1 Server (`server/ladder/goals.js`, `daily.js`, `goals-catalog.json`)
- A game's month is keyed `YYYY-MM` for SMZ3 (the months already stored stay SMZ3's) and `z3:YYYY-MM` / `sm:YYYY-MM`
  for the others, in `db.months`, `db.runs`, the payout grant id (`goals-` + key, so SMZ3's stays `goals-YYYY-MM`) and
  `goals-override.json`. Every use of the month for dates (`monthEnd`, `prevMonth`) takes the date part of the key.
- `pick`: SMZ3 keeps its seed (`goals:YYYY-MM`) and its groups (zelda, metroid, shared), so this month's SMZ3 goals do
  not change. ALttP draws from zelda and shared, Super Metroid from metroid and shared, seeded `goals:z3:YYYY-MM` /
  `goals:sm:YYYY-MM`. A catalog goal can name its games (`"games": ["smz3"]`); `swaps` gets it, since a single game
  never swaps.
- `GET /api/goals?install=&game=`: `game` as the ladder routes take it (missing = smz3, unknown = 400).
- `POST /api/goals/report`: the game comes from the run id's first letter, which every host already writes
  (`z` ALttP, `m` Super Metroid, anything else SMZ3).
- `daily.finishesIn(month, game)` counts only that game's daily windows (`gameOfWindow`), for the `daily` goal.
- The gem balance stays one per install; each game's goals pay into it.
- Runs reported before this change all went into SMZ3's month (this month: 2 Super Metroid runs, 1 ALttP run). On
  load, a month not yet paid moves runs with a `z`/`m` id to their game's month.

### 4.2 Hosts
- PC (`pc_online.c`, `pc_main.c`), 3DS (`smz3online.cpp`, `smz3run.cpp`), Android (`OnlineLadder.kt`,
  `NativeMenuScreen.kt`): the goals request adds `&game=` for ALttP and Super Metroid; entering another game from the
  carousel asks for that game's goals at once, and an answer for a game no longer shown is dropped.
- Core: entering another game from the carousel clears the shown goals, so the host asks for that game's at once.

### 4.3 Checks

  and no `game` give the month's SMZ3 goals unchanged; a report with a `z…` run id lands in the ALttP month only
  (checked on a copy of the data, not on the live store).
- PC and Thor: the run list's World goals card and the ladder's World tab change with the game.
